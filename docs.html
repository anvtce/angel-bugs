4. Luồng đặt lịch 6 bước

Luồng booking là tính năng quan trọng nhất — cần test rất kỹ. Mỗi bước phải pass checklist riêng + chuyển bước mượt mà.

  1. 1

    Bước 1 — Chọn dịch vụ

    /angel/booking

    Hiển thị các nhóm dịch vụ + thẻ dịch vụ. Bấm chọn 1 dịch vụ.

    Cần kiểm tra

    • check_box_outline_blank Có thể bấm vào từng tab nhóm dịch vụ (Manicure, Pedicure...)
    • check_box_outline_blank Thẻ dịch vụ hiện đúng tên, giá, thời lượng
    • check_box_outline_blank Bấm Next Step khi chưa chọn → phải bị chặn / disabled
    • check_box_outline_blank Bấm chọn dịch vụ → nút Next sáng lên
  2. 2

    Bước 2 — Chọn kỹ thuật viên

    /angel/booking/artist

    Liệt kê staff + tuỳ chọn 'No preference '.

    Cần kiểm tra

    • check_box_outline_blank Hiển thị đủ tất cả thợ đang Active
    • check_box_outline_blank Có lựa chọn 'No preference '(hệ thống tự gán)
    • check_box_outline_blank Nút Go Back về Bước 1 vẫn giữ dữ liệu đã chọn
    • check_box_outline_blank Bấm Continue to Schedule → chuyển bước
  3. 3

    Bước 3 — Chọn ngày &giờ

    /angel/booking/schedule

    Lịch + danh sách khung giờ trống (gọi API availability).

    Cần kiểm tra

    • check_box_outline_blank Calendar không cho chọn ngày trong quá khứ
    • check_box_outline_blank Khung giờ phải khớp giờ mở cửa của tiệm (kiểm tra ngày Chủ Nhật / ngày nghỉ)
    • check_box_outline_blank Khung giờ đã có booking khác → phải bị ẩn / disabled
    • check_box_outline_blank Đổi ngày → load lại khung giờ tương ứng
  4. 4

    Bước 4 &5 — Thông tin khách &xác nhận

    /angel/booking/review

    Form họ tên, email, SĐT, ghi chú + tóm tắt đơn.

    Cần kiểm tra

    • check_box_outline_blank Validate email đúng định dạng
    • check_box_outline_blank Validate SĐT (NZ format hoặc số tối thiểu)
    • check_box_outline_blank Bỏ trống các field bắt buộc → báo lỗi
    • check_box_outline_blank Tóm tắt hiển thị đúng: dịch vụ, thợ, ngày giờ, tổng tiền
    • check_box_outline_blank Bấm Confirm Booking → tạo booking thành công, không trùng giờ
  5. 5

    Bước 6 — Xác nhận thành công

    /angel/booking/success

    Hiển thị mã đặt lịch (AN-YYMMDDXXXX) và hướng dẫn.

    Cần kiểm tra

    • check_box_outline_blank Hiển thị mã booking đúng định dạng AN-XXXXXXXXXX
    • check_box_outline_blank Có nút Return to Home dẫn về /
    • check_box_outline_blank Refresh trang vẫn xem được (đã có cookie / state)
    • check_box_outline_blank Email xác nhận được gửi (kiểm tra log server hoặc inbox khi tích hợp Resend)

6. API Endpoints chính

Tester API có thể dùng Postman / Insomnia. Tất cả route dưới đều có prefix /angel .

Booking công khai

Method Path Mô tả
POST /api/bookings Tạo booking mới — chống trùng giờ
POST /api/bookings/availability Lấy khung giờ trống theo ngày + staff
POST /api/bookings/lookup Tra cứu booking bằng email/SĐT
GET /api/bookings/[reference] Xem booking theo mã
PATCH /api/bookings/[reference] Cập nhật / huỷ booking

Gift Cards

Method Path Mô tả

7. Checklist QA tổng thể

Authentication &phân quyền

  • check_box_outline_blank Truy cập /admin khi chưa đăng nhập → redirect về /admin/login
  • check_box_outline_blank Đăng nhập sai mật khẩu → báo lỗi rõ ràng
  • check_box_outline_blank Đăng xuất → cookie/session bị xoá, không truy cập lại được
  • check_box_outline_blank Role STAFF không truy cập được module ADMIN-only (Settings users, Audit Log...)
  • check_box_outline_blank Đổi mật khẩu hoạt động (modal Profile)

Đa ngôn ngữ (VI / EN)

  • check_box_outline_blank Toggle VI/EN ở sidebar và header — chuyển ngôn ngữ ngay tức thì
  • check_box_outline_blank Toàn bộ label admin có bản dịch (không bị thiếu key)
  • check_box_outline_blank Định dạng số / ngày phù hợp locale (en-NZ)

Responsive — Mobile

  • check_box_outline_blank Mobile bottom nav hiển thị Home / Book / + / Stock / Profile
  • check_box_outline_blank Hamburger menu mở được sidebar đầy đủ
  • check_box_outline_blank Bảng / form không bị tràn ngang
  • check_box_outline_blank Booking flow hoạt động trơn tru trên mobile

Responsive — Tablet &Desktop

  • check_box_outline_blank Sidebar admin cố định bên trái ≥ md
  • check_box_outline_blank Calendar Appointments không vỡ layout
  • check_box_outline_blank Modal căn giữa, không bị scroll lock

Performance &UX

  • check_box_outline_blank Trang load <3s (LCP)
  • check_box_outline_blank Loading state hiển thị khi đang fetch API
  • check_box_outline_blank Empty state hiển thị khi không có dữ liệu
  • check_box_outline_blank Error state hiển thị khi API fail
  • check_box_outline_blank Không có console error / 404 asset

Bảo mật

  • check_box_outline_blank Không bypass được /admin bằng URL trực tiếp
  • check_box_outline_blank API admin trả 401 khi không có session
  • check_box_outline_blank API admin trả 403 khi sai role
  • check_box_outline_blank Form public có rate-limit (thử spam 20 booking liên tục)
  • check_box_outline_blank Input có sanitize — thử nhập <script >alert(1)</script >

Dữ liệu

  • check_box_outline_blank Tạo booking trùng giờ cùng staff → bị từ chối
  • check_box_outline_blank Huỷ booking → trạng thái đổi sang CANCELLED, không xoá khỏi DB
  • check_box_outline_blank Audit log ghi lại mọi thao tác CREATE / UPDATE / DELETE
  • check_box_outline_blank Số tiền lưu cents, hiển thị $ đúng (chia 100)
  • check_box_outline_blank Mã booking đúng format AN-YYMMDDXXXX
  • check_box_outline_blank Mã gift card đúng format AN-XXXX-XXXX

8. Edge cases &test khó

Những trường hợp khách hàng thật sẽ gặp nhưng dev hay quên. Vui lòng test kỹ.

  • flag Đặt lịch đúng phút giao giữa hai khung (ví dụ 12:00 khi thợ nghỉ trưa 12:00–13:00)
  • flag Đặt lịch vào ngày tiệm đóng cửa (Chủ Nhật)
  • flag Tạo booking → ngay lập tức huỷ → tạo lại đúng giờ đó (phải thành công)
  • flag Thay đổi giờ mở cửa trong Settings → khung giờ booking phải cập nhật theo
  • flag Tắt 1 staff (available=false) → không xuất hiện ở Bước 2
  • flag Tắt 1 dịch vụ → không xuất hiện ở Bước 1 và trang /services
  • flag Khách điền email trùng với khách cũ → phải merge vào client cũ chứ không tạo bản ghi mới
  • flag Gift card hết số dư khi redeem một phần — phải báo đúng số dư còn lại
  • flag Gift card hết hạn → không cho redeem
  • flag Upload ảnh >5MB → phải có giới hạn / báo lỗi
  • flag Upload file không phải ảnh (.exe, .pdf) → phải bị từ chối
  • flag Tải lại trang giữa booking flow → state không bị mất (BookingProvider giữ trong session)
  • flag Mở 2 tab cùng đặt 1 khung giờ → chỉ 1 tab thành công, tab còn lại báo conflict
  • flag Đăng nhập tab A, đăng xuất tab B → tab A khi gọi API admin phải bị 401
